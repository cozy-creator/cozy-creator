# Typed calls through separate installed environments

This is a real CPU package chain (caller → child → leaf without managed dependency extras → private self call), executed with `cozy run` in the default home. The leaf computes primality with SymPy and an xxhash fingerprint through a private self call and can raise an `InvalidRequest`.
The leaf also exports a pure memoized square operation whose integer result reaches the caller.
Acceptance builds the leaf as a real wheel; the diagnostic operations are not memoized.
The middle child receives and returns an image and
reads one value from an explicitly selected local checkpoint. The caller must import and
install neither `typed_child` nor the callee-only dependency `xxhash`; its result reports those facts and both Python
executable paths. Both children declare private operations, omitted from generated code. The leaf deliberately
has no `cozy-calls` extra: uv retains its ordinary dependencies when that extra is requested.

The caller's `child_calls.py` is generated by the candidate Runtime:

```sh
cozy-runtime --dir caller calls xs198-typed-leaf child/typed_child/leaf_calls.py
cozy-runtime --dir caller calls xs198-typed-child caller/typed_caller/child_calls.py
```

Before generation, lock the caller against the matched Runtime/TensorFS wheels and the
adjacent child. Acceptance also builds and locks the leaf wheel as described below.
Pin both SDK sources in copied fixtures; declare TensorFS directly in those copies so its
source participates in uv resolution. Do not point at a live SDK worktree or publish these fixtures.

In a normal Cozy project, after the coordinator installs the candidate machine/Runtime:

```sh
cozy run /absolute/fixture/caller/run --on local --json
cozy run /absolute/fixture/caller/run fail=true --on local --json
cozy model install /absolute/one.safetensors local/xs198-one --source-format as-is --on local
cozy model install /absolute/two.safetensors local/xs198-two --source-format as-is --on local
cozy run /absolute/fixture/caller/run choice=local/xs198-one --on local --json
cozy run /absolute/fixture/caller/run choice=local/xs198-two --on local --json
```

Use two tiny local F32 safetensors files with different first values. Both model calls must
return their actual first value and different checkpoint identities. The media result must
be PNG with pixel (0,0) equal to RGBA (7,11,19,95); the failure result must carry
`typed_fixture_failure` and a nonempty child request identity. Every result must report
`child_installed=false`, `callee_dependency_installed=false`, and different caller/child Python paths.
Do not claim process or custody qualification from source description or imports alone.

The published declaration is `[project.optional-dependencies] cozy-calls = ["child[cozy-calls]"]`.
The middle package declares its own onward edge the same way. Wheel `Requires-Dist` entries
carry the recursive closure. The first result must also return a nonempty `descendant_python`
from the real leaf; middle and leaf share the held managed environment.

## Shared machine layer

The platform deliberately exposes its shared Torch layer to every Python package (cl-715),
including transitive dependencies such as SymPy. This fixture preserves that guarantee.
It reports `shared_torch_available`, `shared_sympy_available`, and `torch_imported` separately;
availability does not establish an import. The actual inspected local Torch2.15.0+cu132
layer contains Torch/SymPy and contains neither xxhash nor the fixture packages.
The leaf now uses xxhash for a real 64-bit fingerprint of the requested number, forwarded
through B to A as `fingerprint`; the successful media case must contain 16 hexadecimal
characters. Only the callee-specific dependency's absence is asserted. The Python SDK
change does not promise a Torch-free platform environment; native execution is xs-153.

## Acceptance runner

The existing CLI e2e harness selects this cell with `--shard typed-calls`. Its normal
start installs the candidate cohort in the default home and creates the project. The cell
copies these three packages into `$OUT/typed-calls/fixture`, pins the exact `--runtime`
and `--tensorfs` wheels in each, builds the leaf wheel, locks the caller, verifies all
three locked hashes, and regenerates both reference modules with that same pair's public
`cozy-runtime calls` command. TensorFS is declared directly in the copies so its source participates in
transitive resolution; the authored Runtime range and Runtime's TensorFS range still apply.
It then runs the assertions below; all locks,
generated modules, commands, watch records and outputs remain under `$OUT/typed-calls`.
The shard needs Linux and both local candidate SDK wheels. It rents no machine, downloads
no model weights, and creates only two tiny local F32 checkpoints.

```sh
bash e2e/cli/run.sh --out /absolute/fresh-receipts --shard typed-calls \
  --tensord /absolute/candidate/cozy --tensorfs /absolute/candidate/tensorfs.whl \
  --runtime /absolute/candidate/cozy_runtime.whl --packages /absolute/packages
```

Use the existing e2e workflow's isolated Hub wrapper and candidate setup for CI, with
`select=cli` and `shards=["typed-calls"]`; no CPU model suite or GPU lane is needed.
The usual `e2e-cli-linux-typed-calls` artifact includes this cell's receipts.

`references.py` compares generated modules from the actual wheel lock under Python 3.12
and 3.13, and from the leaf's public source/interface description. Fresh real leaf wheels
with a changed request default or bound must fail public source description with
`stale_call_reference`. Their receipts live under `typed-calls/references`;
`qualified.json` there covers source preparation only. The ordinary `cozy run` media
and assets cases separately require the memoized leaf's actual result, `squared=289`.

After the coordinator installs the combined candidate, run this cell from the Creator
checkout with an existing normal Cozy project and a fixture copy locked on that candidate:

```sh
uv run --no-project e2e/cli/typed-calls/run.py \
  --project /absolute/cozy-project \
  --fixture /absolute/typed-calls-fixture \
  --out /absolute/fresh-receipt-directory \
  --model-prefix xs198-typed-proof-01
```

The default CLI is `~/.cozy/bin/cozy` (pass `--cozy` when the coordinator supplies another
CLI). The runner never changes services, homes, roots or SDK policy. It preserves command
receipts and full watch records, exports and inspects the image, creates two tiny local F32
model files, checks both explicit child model choices, checks caught failure propagation,
and requires `callable_internal` for a direct request to the private leaf. Use a fresh output
directory and local model prefix each time. `qualified.json` is written only after all
assertions pass; failed receipts and any still-running job remain available for inspection.

The hard-cut SDK cell also calls `shade_assets` using one typed request and `assets=Files(...)`.
Its handler declares the input as `pictures`, so this checks that the generated binding
preserves the actual Files parameter name. It calls its own async helper directly in the
same attempt, while the leaf's private operation remains an explicit managed self call.
Every model override is passed in `models={...}`; removed request keyword/dict forms are
not used by the fixtures. The cell's image values use `ImageFile.from_image`, not removed
Outputs image methods.
