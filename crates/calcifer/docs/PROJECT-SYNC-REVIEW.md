## Agreed architecture

- Calcifer owns the project engine. A trusted project server runs on the owner's computer or a dedicated rented CPU worker, holds the project's decryption key, serves authorized content and accepts edits. Owner/custodian devices provision that key directly to the trusted server. Ordinary collaborators receive content and use their own access credentials. [Serving roles and flow](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-serving-model.md#L19-L40)
- TensorHub supplies identity, discovery/relay and encrypted backup. Its application/storage receives ciphertext without the project secret or recovery secret. The rented project host is trusted with plaintext, so its hosting operator remains within that trust boundary. [Trust boundary](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-serving-model.md#L19-L24), [key custody](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-encryption-contracts.md#L31-L36)
- Every participating user's local Calcifer and the shared server hold an Automerge replica. They exchange original logical changes and fetch media separately. Hosted backup retains encrypted objects, change history and checkpoints with durable receipts. Local filesystem encryption and hosted replication have separate settings, allowing an ordinary local project to use encrypted hosted backup. [Replica model](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-encryption-and-backup.md#L40-L49), [settings](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-encryption-and-backup.md#L71-L78), [publication](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-encryption-contracts.md#L72-L80)
- Ordinary access-key removal closes server access. Compromise of a key-holding custodian/server requires full retained-project re-encryption. The baseline server key lives in memory, with owner reprovisioning after restart. [Revocation](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-sharing-revocation.md#L5-L18), [server lifetime](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-serving-model.md#L48-L54)

## Implemented at the reviewed snapshots

- RC exposes `cozy push` and `cozy pull`. Each invokes the current project's HTTP transfer endpoint, then watches progress. Calcifer spawns that requested transfer and returns HTTP 202. This continues independently of the initiating client, but starts from an explicit request. [CLI](https://github.com/cozy-creator/cozy-creator/blob/ea64da465e0212f712ecf40e4cac9c38bd8c92c9/crates/cli/src/lib.rs#L67-L80), [request path](https://github.com/cozy-creator/cozy-creator/blob/ea64da465e0212f712ecf40e4cac9c38bd8c92c9/crates/cli/src/project.rs#L51-L81), [handlers](https://github.com/cozy-creator/cozy-creator/blob/ea64da465e0212f712ecf40e4cac9c38bd8c92c9/crates/calcifer/src/project/remote.rs#L363-L406)
- Push reads known project files and uploads raw `Payload::File`/`Payload::Part` bytes, retaining them through the account's private `project-assets` model commit. Pull fills missing files from an already opened project's file list. These operations implement content-addressed file transfer. They do not exchange the project's logical CRDT history or implement the planned encrypted backup protocol. [Raw upload](https://github.com/cozy-creator/cozy-creator/blob/ea64da465e0212f712ecf40e4cac9c38bd8c92c9/crates/calcifer/src/project/remote.rs#L197-L281), [pull](https://github.com/cozy-creator/cozy-creator/blob/ea64da465e0212f712ecf40e4cac9c38bd8c92c9/crates/calcifer/src/project/remote.rs#L330-L368)
- The local-project feature adds canonical Automerge storage and local encrypted sessions. Its push handler explicitly refuses encrypted projects with `encrypted_project_push_unavailable`, explaining that the existing protocol uploads plaintext. [Local document](https://github.com/cozy-creator/cozy-creator/blob/016eefa24376fc1d48dcd309383760e1c9268e7e/crates/calcifer/src/project/crdt.rs#L1-L29), [local vault](https://github.com/cozy-creator/cozy-creator/blob/016eefa24376fc1d48dcd309383760e1c9268e7e/crates/calcifer/src/project/vault.rs#L1-L35), [upload refusal](https://github.com/cozy-creator/cozy-creator/blob/016eefa24376fc1d48dcd309383760e1c9268e7e/crates/calcifer/src/project/remote.rs#L245-L250)
- Configured background project synchronization is unimplemented in these snapshots. The shared `CalciferConfig` exposes only a loopback port, while the existing transfer starts through the request handlers above. The owning issue explicitly defers multiplayer, collaboration hosting and TensorHub backup. [RC configuration](https://github.com/cozy-creator/cozy-creator/blob/ea64da465e0212f712ecf40e4cac9c38bd8c92c9/crates/api/src/config.rs#L46-L71), [feature configuration](https://github.com/cozy-creator/cozy-creator/blob/016eefa24376fc1d48dcd309383760e1c9268e7e/crates/api/src/config.rs#L46-L69), [delivery order](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/tracker/cross-cutting/xs-160-project-encryption-and-backup.md#L56-L64)

## Current direction and remaining work

The current user direction is automatic synchronization owned by Calcifer and enabled/configured per project. The concurrent cleanup retires the legacy manual CLI, HTTP and UI transfer/upload surface while preserving file reads and materialization needed by active project workflows. This report describes the pre-cleanup snapshots and makes no completion claim for that implementation.

A future implementation would use project settings for encrypted backup and background exchange of changes and media. Hosting and its setup are deferred. Exact setting names and transport wiring remain implementation work. Earlier prose allowed manual push/pull through the future encrypted protocol, but the current user direction removes that proposed manual interface. [Separate settings](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-encryption-and-backup.md#L71-L78), [earlier manual-interface proposal](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-encryption-and-backup.md#L370-L378)

Connected delivery still needs replica transport/admission, trusted-server provisioning, ciphertext publication/retention and durable receipts. The existing research explicitly sequences local persistence, then local encryption, then those connected features. Source presence and local tests alone establish no deployed multiplayer or cloud-backup capability. [Research sequencing](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-sync-research.md#L5-L9), [deferred stages](https://github.com/cozy-creator/tracker/blob/417f0a4b36e95e36708ae3ee44009123d198297a/design/project-encryption-and-backup.md#L388-L396)
