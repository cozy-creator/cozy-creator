# Checked consumer-stream retirement

Actual SDXL run26943 stopped in `cuStreamIsCapturing` from `Pin::into_fenced_region` during delayed private storage GC. Runtime had synchronized and retired/destroyed its Domain streams; the old private Use family still retained raw stream integers. This change makes `working::retire_stream` cover tracked source families as well as Working allocations. It changes no allocation, admission, eviction or ledger byte policy.

`StreamUses` is shared metadata for declared consumers. Each declaration retains a process-local stream epoch from one weak registry keyed by device/handle. Successful retirement checks the live stream under that epoch's gate, updates the existing Working retirement state, then marks the epoch complete and removes its current registry entry. No fallible operation follows completion publication. A refusal leaves completion unpublished and requires the caller to retain the stream. If source families exist without an initialized Working device, retirement explicitly refuses instead of inventing a completion witness.

Final Pin release locks epoch gates in stable ID order. It installs fences only on still-live epochs, or uses checked completion when all declared epochs retired. Therefore delayed aliases never query a retired handle. A later declaration opens a new epoch, including when CUDA reuses the same raw address; old aliases retain their completed witness. The registry is weak and removes dead entries, rather than keeping permanent retired-handle tombstones. Caller obligations remain explicit: close both submissions and declarations before retirement; keep the stream live until success; and declare every later use on a live stream. Arbitrary external destruction without retirement is not supported.

The lock order is a consumer-family lock, sorted epoch gates, then existing capture/arena or Working locks. Declaration takes the registry only to acquire an epoch and releases it before taking the family lock. Retirement releases native capture/Working locks before registry publication. Epoch final drops never occur while the registry is held. No path acquires Python's GIL or adds a GPU wait in a storage destructor.

Private Use and every independently exported DLPack Storage structurally share the same `Arc<SharedPin>`. Temporary storage or Use destruction only releases its ownership share; it does not separately fence a cloned Pin during capture. One core pointer-family registration stays valid while that actual owner remains, so later `Tensor.record_stream` also reaches private storage. Only the final shared owner releases the physical Pin. Fill commit joins the producer and transfers the resulting lease to the already-exported owner; abort and failure stay fail-closed.

This relies on concrete existing Runtime custody, not a sibling reference-count observation: resident Binding preparation retains the canonical private Use/tensor; LoadSlot caches the actual from-DLPack Storage and Binding retains its typed views through `graph.end`/`abort`. LoadSlot's work owner remains independent so an escaped exported lease is still observable after Runtime clears its own tensors. Naked LoadSlot capsule export now receives an explicit actual consumer stream, and DLPack protocol stream arguments are honored. No footprint-as-weight-manifest or graph-lifetime physical pinning is introduced.

Genuinely final storage destruction during an unowned/uncertain capture still retains the exact Pin. Private failures use the existing per-device retirement quarantine; typed public exports keep their existing Source/service quarantine. An unannotated raw Use that exported no Storage retains its existing context-joined reclamation contract. Published private Storage requires a consumer declaration.
