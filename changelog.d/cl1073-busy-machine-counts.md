- A run goes to an idle machine rather than a busy one that would finish it later: each run going on a machine counts what its time left says, where it counted its function's time less the time since its executor started, so a machine whose runs were still downloading and loading their weights looked seconds from free. A machine whose update waits for its runs to end starts nothing new before it has, and is quoted so. A run waiting for a rental or added machine, in its queue or held for its update, moves to another of its machines that would finish it clearly sooner, the same run. Of machines that finish together, the sooner wins, never the first listed (cl-1073).
- A run takes every GPU of its machine that its function declares it can use (Paul 11-16: "always use parallelism when possible"): a multi-GPU machine is no longer split into one-GPU runs, nor a declared width held back until it was measured faster; the next run waits for them or goes to another machine, whichever finishes it first (cl-1073).
