TensorD's `appended_from` is the length of the leading parts a revision shares with the one before, digest and length alike, part by part from the start (cl-1210): a growing video keeps all of its last revision but its index, so Calcifer copies those bytes and reads only the new ones. A follower holding more than a revision keeps is reset. A run's record says what this computer downloaded of each result and what it kept of the revision it held (`measurements.transfer.<output>`: `read`, `reused` bytes over its revisions; `downloaded` in `cozy run watch --full`), and a run whose kept bytes failed the file's digest, so that it was downloaded whole again, carries the warning `output_reread`.
