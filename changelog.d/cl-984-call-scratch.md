One code path for every project's runs (Paul, 11-15: file and record isolation only; executors are the machine's). Every call gets a scratch folder inside its project (the machine's for a run of none), `Invoke.scratch`, and its project's store, `Invoke.store`: the Runtime keeps the call's temporary files, working directory, HOME and stdout/stderr there and TensorD removes the folder after the run. An unlocked encrypted project's runs use the same executors as a plaintext one's; the per-project executor code is gone. A failed run's stderr tail is its call's own. No executor writes a core (cl-984).
