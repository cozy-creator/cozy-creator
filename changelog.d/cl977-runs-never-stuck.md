Runs never get stuck (cl-977, Paul 11-15). TensorD watches each executor it waits on, thread by thread. An executor where, for 60 s, no thread used CPU or moved a byte, none waits on time or on a TCP peer that still answers, its GPUs ran no kernel, and TensorD did no work for it, is hung. TensorD kills it, and the run fails `hung`, so the machine's idle clock can run again. One killed but stuck in the GPU driver, holding every GPU, marks the machine `broken: stuck_in_driver`, and a rental then releases itself. Nothing judges how fast a run goes: a slow run that still works, a sleep, a call waiting on a live remote, or a wait on its own child call is never touched. The Runtime's own watcher threads (named `~…`) and varena's donors don't count as life. A package install, a describer and the codec helper are watched the same way. `cozy run` and `cozy run watch` no longer stop with exit 4 on a run that makes no progress: they show the warning and follow on to the run's end.
