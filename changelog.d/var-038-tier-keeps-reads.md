A model that streams through a small GPU reads its weights from disk or the page cache once, not every pass (var-038). A block read again from the store (an LM's layers each token at 6 GiB, a denoise loop's streamed blocks) is read into a pinned host page the host tier admits and filled onto the card from there, so every later pass is one DMA. Before, such a page entered the tier only between requests, by a second read, so the first request never got it: Klein's prompt upsampler at 6 GiB re-read 924 GB from the page cache over 272 tokens, HunyuanImage 3's thinking 5.94 TB. The next refill's page is made ahead on the tier's thread. A first fill still reads straight onto the card.
The host tier pins at most half of the memory this process may use (its container's or executor's limit, else the computer's), not half of physical memory: in a 30 GiB container it could pin past what the container holds and starve the page cache the rest of a model is read through.
