A package install's failure is judged from what TensorD reads itself, never uv's words, which stay its shown detail: the disks uv writes, sampled each second it runs and once after, at or under their reserve is `machine_disk_full`; a host the step needed (the lock's registry, wheel or git hosts, the index) that doesn't answer TensorD now is `hub_unreachable`, asked again, naming the host; anything else is `package_installation_uv_failed`. A lock for another architecture is refused before an environment is made, naming where it runs (its `supported-markers`' `platform_machine` as well as `sys_platform`). A wheel uv finds no tag for here is `package_installation_uv_failed` with uv's words, no longer `release_platform_unsupported` with "ask its author to support this platform" (xs-220, hack audit tensord #5).
