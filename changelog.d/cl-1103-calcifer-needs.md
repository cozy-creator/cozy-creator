A machine gets ready for the request Calcifer predicts, and plans it as that request (cl-1103, cl-1123):
- A box's draft becomes the exact run a Render of it would send: bound as a render binds it (a mention of a box not rendered yet counted as its kind), its seed drawn at draft time and taken by the Render. That run goes to the machine the Render would land on as a prepare item, and a walk's planned jobs go as upcoming items. The machine plans each one as the call it is: the package's needs rules on its payload, its precision lane for that GPU, its own store. It fetches exactly that request's needs at the list's priority. A Qwen Image 2 box drafted text-to-image gets the model and `expander_t2i`, never `expander_i2i`. Editing the draft to mention a picture makes it another request: the machine stops what only the old one wanted and fetches `expander_i2i`.
- Each item's readiness (`installing`, `downloading`, `ready`) shows in the machine's Status, and the Render names the item it was predicted by.
- A render's quote counts exactly what its request waits for, less what that machine has: a model its rules rule out isn't counted, one they rule in is, and an on-demand model no rule answers is no part of it ("plus up to … on demand" is gone). `cozy run`'s placement quotes its bound payload the same way.
