A Region's fill copies each stored object range from where it already is, before the store: another set's resident Region on the same GPU (one device copy that waits for no compute), else that set's kept host page (a pinned copy), else the store. Sources are indexed by content, so a LoRA view and its base (the same chunks, renamed) share their bytes, and a copied page keeps its place in the reclaim order (`Region::try_pin_unused`). A caller's first LoRA on Klein base (int8, RTX 4090, one pod) filled its 9.9 GB from the card at 104 GB/s instead of the store at 4.4 GB/s: step 1 1.28 s against 2.27 s (no LoRA: 0.30 s), outputs byte-identical, steady steps unchanged (runs 42060, 42065). Each origin is its own fill row (`resident`, `host`, `store`).
