A Region's fill copies each stored object range from where it already is, before the store: another set's resident Region on the same GPU (one device copy that waits for no compute), else that set's kept host page (a pinned copy), else the store. Sources are indexed by content, so a LoRA view and its base (the same chunks, renamed) share their bytes: a caller's LoRA no longer re-reads the whole DiT from disk before it bakes. Each origin is its own fill row (`resident`, `host`, `store`).
