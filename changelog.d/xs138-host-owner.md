Host RAM is varena's (REVIEW #3): `varena_ledger::host` sizes one number from what the kernel accounts, the computer's reserve for programs outside cozy left out, and every client draws on it with no budget of its own: the host tier's weight pages, spilled retained state and spares; the page cache a read or TensorD's read-ahead fills (only memory nothing holds, so a store larger than RAM streams O_DIRECT instead of thrashing the cache); and staging and each process's own memory, which the kernel charges. A contained machine's `memory.max` is that number: TensorD writes it and sizes nothing. Executors share it through a host ledger page: an idle process gives its pinned pages back to a call that is short, and TensorD ends an idle executor when that isn't enough, as v1 did at a model switch. Clean page cache counts as reclaimable, and the reserve is kept once, never stacked on a fixed headroom. Fixes the 0.21.2 matrix's paging rows on a 31 GiB host (Flux-2 +72–212%, H3 +40–120%, Klein 8 GiB +49%).
