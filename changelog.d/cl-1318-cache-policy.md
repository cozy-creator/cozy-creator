A read keeps the weights it reads in RAM (cl-1318): it goes past the page cache only when the machine's one host admission (`varena_ledger::host::admission`, the number pins are admitted against) couldn't keep its bytes once the clean cache gives way, where a cache full of older bytes sent every later read past it (H3's text encoder in a fresh executor read 9.6 GB of 26.4 again from disk). Then a range the cache partly holds reads only its holes from disk and the rest from the cache. A release-gate session can ask for a pod with a small memory number (`max_memory_gb`).
