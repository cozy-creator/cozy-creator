A LoRA that names no model slot (`cozy run --lora <lora>`, or one dropped on a box) goes on the slots whose model takes LoRAs (the package interface's `loras`), never on the first slot built. On FLUX.3 Klein's, Fibo's and Krea 2's boxes it went on the text encoder and the run was refused; now it goes on the box's model, Base or distilled, whichever the render loads. A function that loads two such models at once refuses it in one line naming each slot and what to type. A refusal moved earlier: on a function none of whose models takes LoRAs (flux-2, hidream-o1, hunyuan-image-3, ideogram-4, ltx-2.5, pan2, qwen3, relayvsr, seedvr2, birefnet, and minimax-h3's VAE and latent-upscale functions), a LoRA is refused as `lora_slot_absent` before anything downloads, where it used to fail as the model loaded (`adapter_incompatible`). Both need the package locked on a Runtime that writes `loras` (cl-1241).
